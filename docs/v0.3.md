# BinX v0.3 ELF analysis

BinX v0.3 understands ELF32 and ELF64 executables and shared objects without loading or executing them.

## Commands

- `binx inspect file` — complete ELF report
- `binx sections file` — section headers
- `binx segments file` — program headers / load layout
- `binx symbols file` — SYMTAB and DYNSYM entries
- `binx dynamic file` — dynamic tags
- `binx notes file` — ELF notes
- `binx relocations file` — REL/RELA relocations

All support `--json` and `--output`.

## Supported structure

The parser validates the ELF identification bytes, class, byte order, header sizes, program-header and section-header ranges, section contents, symbol entry sizes, note boundaries and relocation bounds. Invalid structures generate stable diagnostics rather than causing out-of-bounds reads.

The parser supports the standard ELF32 and ELF64 layouts and both little- and big-endian byte order. The machine decoder currently names common x86, ARM, AArch64, RISC-V and MIPS values while retaining unknown numeric machine IDs.

### Program headers

BinX reports segment type, permissions, file offset, virtual address, file size, memory size and alignment. PT_INTERP is decoded as the runtime interpreter path.

### Sections

BinX resolves names through SHSTRTAB and reports section type, flags, address, file offset, size, link and info fields. NOBITS sections are allowed to have no file backing.

### Symbols

Both SYMTAB and DYNSYM are parsed. Each symbol reports name, binding, type, visibility, section index, value and size.

### Dynamic and relocations

Dynamic tags are decoded numerically and by common symbolic name. REL and RELA entries expose relocation offset, packed info, symbol index, relocation type, optional addend and resolved symbol name when available.

### Notes

ELF note records expose owner name, note type and descriptor size/data. No note is executed or interpreted as code.

## JSON

ELF uses schema version 3 so consumers can distinguish it from v0.2 PE schema version 2.

Addresses and offsets are hexadecimal strings where precision matters. Diagnostics remain structured with stable codes.

## Safety

The ELF parser is pure data analysis. BinX does not execute the input, load shared libraries, invoke constructors, resolve runtime dependencies, fetch external symbols or contact a cloud service.

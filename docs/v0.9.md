# BinX v0.9 — Crash Analysis

## Scope
BinX v0.9 adds safe, offline inspection of crash dump containers. It never executes code from a dump, loads referenced modules, contacts symbol servers, or downloads external data.

## Windows minidumps
The analyzer recognizes the `MDMP` signature and reads the minidump directory. It extracts the processor architecture from `SystemInfoStream`, exception code/address and crashing thread from `ExceptionStream`, and module base/size/name metadata from `ModuleListStream` when present. Thread stack descriptors are collected from `ThreadListStream`.

## ELF core dumps
The analyzer recognizes ELF files whose `e_type` is `ET_CORE`. It supports little-endian ELF32/ELF64 note traversal, maps common x86/x86-64/ARM/ARM64/RISC-V architectures, counts `NT_PRSTATUS` thread notes and reads the signal from `NT_SIGINFO` when present.

## CLI

    binx crash crash.dmp
    binx crash crash.dmp --json
    binx crash core --json

`crash-analysis` is accepted as an alias for `crash`.

## JSON
Crash reports use schema version 7 and contain format, architecture, thread/module counts, exception/signal information, fault address, crashing thread and a bounded module list.

## Safety
Crash dumps are untrusted input. Parsing is bounds-checked and strictly local. A malformed or unsupported dump returns a structured BinX error instead of being executed.

# BinX v0.6 — Disassembly

v0.6 adds offline, built-in x86/x86-64 disassembly to BinX. It does not execute code and does not require Capstone, LLVM or another runtime disassembly library.

## Commands

    binx disasm program.exe
    binx disassemble program.exe
    binx disasm program.exe --from-entry --count 80
    binx disasm program.exe --json
    binx disasm program.exe --max-bytes 4096
    binx disasm program.exe --syntax intel

`disasm` and `disassemble` are aliases.

## Executable-region selection

For PE files, BinX selects sections marked executable and maps their RVAs to file offsets. For ELF, it selects sections carrying `SHF_EXECINSTR`.

`--from-entry` restricts the analysis to the executable region containing the detected entry point and starts decoding at that address.

## Instruction model

Each instruction records its virtual address, file offset, original bytes, mnemonic, operands, recognition status, and relative branch target when available.

Unknown bytes are emitted as `db` records rather than skipped. This makes offsets deterministic and prevents the disassembler from inventing instruction boundaries.

## Decoder coverage

The built-in decoder covers common x86/x86-64 primitives including `nop`, `ret`, `leave`, `hlt`, `int3`, `syscall`, `push`/`pop`, immediate `mov`, `xor`, `call`, `jmp`, and short/near conditional branches.

This is intentionally a safe baseline decoder rather than full Intel/AMD ISA coverage. Unsupported instructions remain visible as `db` records.

## JSON

JSON uses schema version 4 and preserves addresses, offsets, bytes, mnemonics, operands, validity and branch targets.

## Safety

BinX never executes the target binary, calls a loader, follows control flow by running instructions, accesses the network, or downloads symbols.

No cloud/API functionality is introduced in v0.6.
